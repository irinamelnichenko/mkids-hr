# Форма з сайту → лід у бота

Що потрібно від того, хто веде сайт. Код на нашому боці вже написано
(`webLeadIntake` у `crm_script.js`), але **ендпойнт вимкнено**: поки в Script
Properties немає `WEB_LEAD_SECRET`, будь-який виклик отримує відмову
`{"ok":false,"code":"DISABLED"}`. Інтеграція не почнеться випадково.

## Що передати підряднику

**1. URL.** Той самий веб-застосунок, що вже обслуговує CRM:

```
POST https://script.google.com/macros/s/<ID_ДЕПЛОЮ>/exec?action=webLead&s=<СЕКРЕТ>
Content-Type: text/plain;charset=utf-8
```

`Content-Type: text/plain` — не помилка. Apps Script на `application/json`
відповідає CORS-preflight, якого веб-застосунок не обробляє; з `text/plain`
запит іде як «простий» і preflight не виникає. Тіло при цьому — звичайний JSON.

**2. Секрет.** Згенеруємо ми, передати захищеним каналом (не в листі разом з URL,
не в репозиторії сайту в git). Секрет має лежати на **сервері** сайту.

**3. Тіло запиту.**

```json
{
  "phone":   "+380671234567",
  "loc":     "Осокорки",
  "parent":  "Ірина",
  "child":   "Софія",
  "age":     "3",
  "source":  "сайт|Google",
  "comment": "цікавить група на вересень",
  "hp":      ""
}
```

| Поле | Обовʼязкове | Примітка |
|---|---|---|
| `phone` | **так** | будь-який формат, нормалізуємо самі; мінімум 9 цифр |
| `loc` | бажано | назва локації як у CRM — інакше лід не привʼяжеться до директорки |
| `parent`, `child` | ні | до 80 символів |
| `age` | ні | до 20 символів |
| `source` | ні | типово `сайт\|Google` |
| `comment` | ні | до 300 символів |
| `hp` | **так, порожнє** | honeypot, див. нижче |

**4. Відповіді.**

| Відповідь | Що це | Що робити сайту |
|---|---|---|
| `{"ok":true,"id":"ld_…"}` | лід створено | показати «дякуємо» |
| `{"ok":true,"duplicate":true}` | цей номер уже залишав заявку за останні 24 год | показати «дякуємо» так само |
| `{"ok":true,"ignored":"honeypot"}` | спрацював honeypot | показати «дякуємо» — бот не має знати, що його впіймали |
| `{"ok":false,"code":"BAD_PHONE"}` | телефон не пройшов | підсвітити поле |
| `{"ok":false,"code":"RATE"}` | понад 30 заявок за годину | показати «спробуйте пізніше» |
| `{"ok":false,"code":"FORBIDDEN"}` | невірний секрет | помилка інтеграції, писати нам |
| `{"ok":false,"code":"DISABLED"}` | ми ще не увімкнули | помилка інтеграції, писати нам |

## Захист

Чотири рівні, усі вже в коді:

1. **Секрет у query** (`?s=…`). Викликати ендпойнт наосліп не вийде.
   Тому ж запит має йти **з сервера сайту**, а не з браузера відвідувача —
   інакше секрет видно у вкладці Network будь-кому.
2. **Honeypot** — приховане поле `hp`, невидиме для людини (`position:absolute;left:-9999px`,
   не `display:none` — частина ботів це розпізнає). Заповнене → заявку тихо
   відкидаємо і відповідаємо `ok:true`, щоб бот не підбирав обхід.
3. **Дедуплікація** — той самий номер у межах 24 годин створює лід один раз.
4. **Ліміт частоти** — 30 заявок за годину сумарно.

Чого тут **немає** і що варто мати на увазі: капчі. Якщо на сайті вже стоїть
reCAPTCHA або Turnstile — нехай сайт перевіряє токен у себе перед викликом
нашого ендпойнта. Додавати перевірку капчі на нашому боці не будемо: це
зайвий зовнішній виклик у кожному запиті.

## Як увімкнути, коли сайт буде готовий

1. Script Properties → додати `WEB_LEAD_SECRET` = згенерований рядок (32+ символи).
2. Передати підряднику URL деплою і секрет.
3. Перевірити тестовою заявкою — лід має зʼявитись у групі Telegram
   з джерелом `сайт/Google` і відповідальною за локацією.
4. Видалити тестовий лід з аркуша `Ліди_Бот`.

Вимкнути назад — видалити `WEB_LEAD_SECRET`. Деплой не потрібен.

## Що спитати в того, хто веде сайт

- Чи є на сайті **бекенд**, який може зробити POST, чи форма шле напряму з браузера?
  Від цього залежить, чи можна взагалі використати секрет.
- Які **назви локацій** у формі? Мають збігатися з CRM, інакше `loc` доведеться мапити.
- Чи стоїть капча і яка саме?
- Куди заявки падають **зараз** — щоб не вийшло дублювання в двох системах.
